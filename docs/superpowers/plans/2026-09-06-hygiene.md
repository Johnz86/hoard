### Task 1: The configured hash policy governs a rescan

**Files:** `src/cli/mod.rs` (the `Scan` variant and its tests), `src/main.rs` (the `Scan` arm), `src/cli/scan.rs` (only if the signature must change; prefer resolving the policy in `main.rs`), `docs/handoff.md` (drop the item), `hoard.toml` documentation in `docs/architecture.md` or `README.md` only if either documents `--hash` (grep `\-\-hash`; leave them if they do not).

**Interfaces:**

```rust
Scan {
    #[arg(long)]
    source: Option<String>,
    /// When to compute sha256. Overrides `[index] hash_policy` for this run.
    #[arg(long, value_enum)]
    hash: Option<HashWhen>,
}
```

  `main.rs` resolves the policy as `hash.map_or(context.config.index.hash_policy, Into::into)` after opening the context (open first, then read the config it carries; the flag wins when given). `hoard scan --hash never` still means never; `hoard scan` alone now means whatever `hoard.toml` says, `background` by default, which is what `Later` mapped to, so a config without the key behaves as before. The `HashWhen` doc comments stay; the `Later` variant's comment may say it is the default policy.
