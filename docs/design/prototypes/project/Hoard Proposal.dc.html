Point it at a disk, not at a schema

Onboarding is a scan. The scanner reads headers rather than whole files, so a terabyte is minutes, not hours. Nothing is moved, renamed or rewritten; the index is the only thing that changes.

07

Speak the protocols the tools already speak

Adoption fails if it needs a plugin. One node runs the daemon and exposes three compatible faces on the LAN, so existing scripts, notebooks and UIs keep working with a single environment variable.

PEERS, NOT A SERVER FARM

Every install is a node. Nodes announce themselves on the local network and gossip their index, so the laptop can see the workstation’s 2 TB without holding a byte of it. Pulls go peer to peer over the LAN, resumable, hash-verified on arrival. The internet is a fallback, not the default path.

READ-ONLY BY DEFAULT

Serving exposes reads. Writes need an explicit token per node, and a served path is never a mount — a client asking for a file gets a stream, not a handle to your working tree. No accounts, no cloud dependency, no telemetry.

08

Shelves are queries. Loadouts are the reason you came.

Nobody uses one model. A working setup is a checkpoint plus three LoRAs at specific weights, a controlnet, an upscaler and a VAE. That combination is the real unit of work, and today it lives in someone’s memory. Name it, pin the revisions, hand the manifest to another machine.

loadout: night-exterior-v3 7 PINNED · 31.8 GB · RESOLVES ON 2 NODES
{{ l.role }} {{ l.name }} {{ l.rev }} {{ l.w }}
$ hoard apply night-exterior-v3 --node laptop
→ 5 present, 2 pulling over LAN (1.2 GB/s), symlinks written for comfyui
WHY IT LANDS
Reproducible. Revisions are pinned by commit, so a result from March still resolves in September.
Portable. The manifest is a small text file. It travels in a repo, a chat message or a paper appendix.
Cheap. Applying a loadout writes symlinks into whatever layout the target tool expects. No second copy.
